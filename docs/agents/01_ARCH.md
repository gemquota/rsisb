# Module 1: Architecture Blueprint & System Topography

This module establishes the core system mapping, virtual hierarchy, and data layout. It forms the foundation of the agent's spatial awareness within the repository.

## 1.1 Virtual Layer Hierarchy

The core architecture operates across 9 distinct functional dimensions. While lower layers handle physical code mutation and verification, higher layers process system telemetry to shape long-term behavior.

| Layer | Name | Core Loop / Function | Timescale | Operational Objective |
|---|---|---|---|---|
| **L1** | Execution Loop | Pure terminal execution, git-apply, pytest verification | Seconds | Maintain pipeline reliability and recovery. |
| **L2** | Planning Loop | Goal analysis, step planning, code generation, and evaluation | Minutes | Execute localized code optimizations. |
| **L3** | Self-Direction Loop | Signal detection, goal generation, and priority task assignment | 5–15 min | Manage queue health and balance goals. |
| **L4** | Optimizer Loop | Parameter tuning, algorithm A/B testing, experimentation | 0.5–1 hr | Optimize execution parameters based on logs. |
| **L5** | Evolution Loop | Cross-session pattern detection and consolidation | 2–3 hr | Prune redundant logic; grow structural insights. |
| **L6** | Identity Layer | Self-model management, value reinforcement, and health checks | 4–6 hr | Evaluate behavior against core value axioms. |
| **L7** | Meta-Cognition | Evaluates the quality of the self-improvement process | Daily | Propose architectural "super-goals". |
| **L8** | Meta-Meta | Reflects on the quality of L7 meta-cognition | Daily | Second-order recursive awareness. |
| **L9** | MMM | Third-order self-transcendence and system-wide synthesis | Daily | Drive holistic paradigm shifts. |

## 1.2 Canonical Data Store (rack/) Layout

All state and operational metrics generated by RSIS must reside exclusively within the canonical data rack.

```
rack/
├── RACK_MAP.md                # Aggregated directory index and subrack maps
├── L1/ through L6/            # Subracks dedicated to layer-specific telemetry
├── shared/                    # Matrix variables and shared system memory
├── project/                   # Standalone non-loop operational metadata
└── archive/                   # Cold storage for deprecated or superseded logic
```

> **System Invariant:** The legacy .rsis/ directory must only exist as logical symlinks pointing directly into rack/ to guarantee strict backward compatibility without fragmenting state storage.

## 1.4 Design Principles

- **State Conservation:** All system state lives in `rack/`. No fragmentation.
- **Surgical Precision:** Code changes target only the specific AST node — no wrappers or duplication.
- **Test Absolutism:** All 388 tests must pass before any change is accepted.
- **Manual Oracle Mode:** Evaluations are performed manually by the operating agent (mode="local").
